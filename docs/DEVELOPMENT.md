# Разработка Whale

## Сборка

Логика приложения, CLI, помощник, хранилище и управление соединением написаны
на Rust. SwiftUI остаётся нативным интерфейсом macOS. Xray — отдельный сетевой
движок; его исходный язык и реализация протоколов не менялись.

Требуются macOS 13+, Command Line Tools (`xcode-select --install`) и Rust через
rustup. Toolchain закреплён в `rust-toolchain.toml`, зависимости — в `Cargo.lock`.
Cargo.toml и VERSION должны содержать одинаковую версию приложения.

```sh
make build        # release-бинарники dist/whale и dist/whale-helper
make app          # дополнительно SwiftUI, иконка и dist/Whale.app
make test         # Rust-тесты, rustfmt, clippy
make integration  # настоящий Xray, без TUN и изменения DNS
make test-native  # Swift декодирует снимки Rust-помощника
sh scripts/package-release.sh # архив релиза, лицензии зависимостей и SHA-256
```

Makefile ищет Cargo также в `~/.cargo/bin`; путь можно переопределить `CARGO=…`.
Для сборки приложения положите Xray 26.9.9 в `.tools/xray` либо задайте
`WHALE_BUILD_CORE=/absolute/path/xray`. Скрипт проверяет версию и SHA-256 из
`XRAY_VERSION` и `XRAY_SHA256`. Последний фиксирует проверенный локальный arm64-движок,
а не подпись издателя. Для другой архитектуры требуется отдельно проверить
происхождение бинарника и передать его сумму в `WHALE_BUILD_CORE_SHA256`.
Обновление движка выполняется отдельно и требует интеграционных проверок.

Упаковка релиза выполняется после `make app` и создаёт
`dist/whale-<version>-macos-arm64.tar.gz` и файл `.sha256`. Для сбора лицензионных
уведомлений упаковщику нужны Python 3 и Go; для установки и запуска приложения
они не требуются. Архив включает `Whale.app`, CLI, помощник, Xray и уведомления
сторонних компонентов. Homebrew устанавливает проверенный архив без компиляции.
В этой версии публикуется только проверенная сборка для Apple Silicon.

Сборка предназначена для архитектуры текущей машины. Подпись ad-hoc подходит
для локальной разработки, но не заменяет Developer ID и нотарификацию. Команда
`make app` не устанавливает приложение в `/Applications` и не обновляет системного помощника.

Launcher `./whale` использует `.local` проекта. Установленные GUI/CLI по умолчанию
используют `~/.config/vctl`. `WHALE_HOME`, затем `VCTL_HOME` задают другой профиль;
CLI также принимает `--home`. Для разработки используйте временный профиль.

## Модули

| Модуль | Ответственность |
|---|---|
| `model.rs` | Схема профиля 1, порядок источников, сохранение неизвестных полей |
| `store.rs` | Ограниченное чтение, flock, операции относительно открытого каталога, fsync и атомарная замена |
| `profiles.rs` | VLESS/Trojan, подписки, стабильные идентификаторы серверов |
| `config.rs` | Проверка модели и компиляция маршрутизации/DNS в Xray |
| `sources.rs` | HTTPS-источники, лимиты, пресеты, geodata, независимые обновления |
| `runtime.rs` | Владение процессами, готовность через HTTPS-прокси, применение и откат конфигурации |
| `dns.rs` | Журналирование DNS до изменения, восстановление с проверкой владения |
| `service.rs` | launchd, установка снимков бинарников, проверка UID, протокол управления |
| `cli.rs`, `snapshot.rs`, `latency.rs` | Команды, публичные DTO и отменяемые TCP-проверки |
| `macos/Whale/` | SwiftUI, формы, состояние, системная авторизация |

`cmd/`, `internal/whale/`, go.mod/go.sum сохранены как прежняя реализация и источник
fixtures. Они не входят в `make build` или `.app`. `make legacy-test` запускает их
проверки при наличии Go. Homebrew устанавливает готовую Rust-сборку из релиза 0.6.0.

## Границы прав

GUI и публичный CLI работают без root. Они вызывают `whale-helper`; URL подписки
передаётся через stdin. Snapshot не содержит подписочных URL или outbound с ключами.
В отображаемых URL других источников удаляются userinfo, query и fragment;
неизменённый источник при сохранении формы берётся из профиля, чтобы не потерять токен.

Установка требует системной авторизации macOS или sudo. Контроллер получает
фиксированные пути профиля и защищённого снимка исполняемых файлов. IPC принимает
только действия, версию и номер протокола: произвольные команды, аргументы программ
и пути не передаются. Обе стороны проверяют UID.

Служба использует `/Library/Application Support/vctl/runtime/<uid>-<profile-hash>`.
Каталоги проверяются через `openat` с запретом symlink и записи другим пользователям.
Сокеты находятся в `…/vctl/sockets`, а не в `/var/run`, который на этой системе
доступен для записи группе daemon. Runtime, конфигурации и журнал DNS не находятся
в пользовательском профиле. Root не меняет владельца пользовательских файлов.
Обновляющий процесс необратимо сбрасывает дополнительные группы, GID и UID.

Go-помощник не считается совместимым: протокол 2 требует установки Rust-помощника.
Установка останавливает старую службу и сохраняет прежнее определение для отката
при неуспешном запуске новой. Закрытие GUI не означает отключение VPN.

Установщик дожидается удаления старого задания из launchd после `bootout`: сама
команда может завершиться, пока процесс ещё обрабатывает SIGTERM. Откат также
ждёт остановки нового задания. Неуспешная проверка остановки запрещает повторный
запуск. Ожидание дочерних процессов использует ограниченный по времени `try_wait`,
поскольку системная авторизация AppleScript наследует заблокированный SIGCHLD.

## Состояние и восстановление

Состояния: stopped, starting, connected, stopping, failed. SwiftUI получает также
совместимое поле on/off/starting/unknown. Connected означает, что ядро прошло
ограниченную HTTPS-проверку через прокси и проверку маршрута TUN. TCP-пинг серверов
показывает только доступность TCP-порта, без проверки авторизации.

Профиль хранит желаемые настройки. Runtime сообщает применённый выбор, реальный
сервер и ошибку последнего применения. Перед сменой соединения новая конфигурация
проверяется Xray; неуспешная замена вызывает попытку возврата предыдущей конфигурации.
Если откат тоже не удался, возвращается failed, процессы останавливаются и
выполняется восстановление DNS. Kill switch в этой версии не реализован.

Перед запуском Xray служба записывает и синхронизирует журнал владения процессом.
Промежуточный процесс ожидает разрешения через stdin и только затем заменяет себя
ядром с тем же PID. Авария до записи журнала поэтому не оставляет работающий TUN
без сведений для восстановления. Отключение отменяет уже ожидающие подключения;
удаление службы закрывает приём новых команд подключения.

Каждое изменение DNS предваряется синхронной записью журнала. Восстановление
затрагивает только сервисы, у которых текущее значение совпадает с установленным
Whale: чужие последующие изменения не затираются. Неуспешное восстановление
сохраняет журнал для повторной попытки.
Одна общесистемная блокировка владения TUN защищает подключение и восстановление
между разными профилями, чтобы старый журнал одного профиля не менял DNS другого.

Скачивание и проверка настроек происходят вне блокировки профиля. Перед записью
GUI-команда сравнивает исходный профиль с текущим: при конкурентном изменении
операция сообщает о необходимости повторить действие. Автообновление источников
не удерживает блокировку во время сетевых запросов.

## Пользовательские пресеты

Источник пресета — локальный JSON-файл или HTTPS-ссылка. Поддерживаются также
встроенные источники `builtin:lan` и `builtin:ads`. Формат файла:

```json
{
  "version": 1,
  "description": "Исключения для локальной сети и example.org",
  "rules": [
    {"kind": "cidr", "value": "192.168.0.0/16", "action": "direct"},
    {"kind": "suffix", "value": "example.org", "action": "direct"}
  ]
}
```

Поле `description` необязательно. Требуется от 1 до 5000 правил; неизвестные поля
отклоняются. Типы правил и действия совпадают с разделом Routing. Минимальный
интервал обновления — 60 секунд. Содержимое проверяется до изменения профиля.

## Проверки перед выпуском

Автотесты используют временные профили, loopback, тестовые процессы, фальшивый
системный DNS-адаптер и `xray run -test`. Они не доказывают работу привилегированного
TUN на реальной сети. Перед выпуском отдельно проверить:

- Установку, обновление и удаление контроллера, отмену авторизации, перезапуск macOS.
- Подключение и отключение, закрытие GUI, смену сервера, откат при отказе ядра.
- SIGTERM/SIGKILL контроллера и ядра, сохранение и восстановление системного DNS.
- Смену Wi-Fi/Ethernet, сон и пробуждение, IPv6, изменения DNS сторонними программами.
- Правила приложений, дочерних процессов, доменов, UDP и QUIC.
- Сохранение ввода при ошибке формы, устаревший статус и отмену пинга.

Эти сценарии требуют отдельной сессии: остановка рабочего VPN может прервать связь.
Подписанный релиз, notarization и обновление Homebrew/cask выполняются отдельно.
