# Разработка и сопровождение

Пользовательская инструкция — в [README](../README.md).

## Локальное окружение

Скачайте репозиторий и откройте терминал в его каталоге. Проверьте, что
`python3 --version` показывает Python 3.11 или новее, затем выполните:

```sh
python3 -m venv .venv
.venv/bin/python scripts/install-core.py
./scripts/vctl-launcher --help
```

Установщик скачивает архив Xray для архитектуры Mac из официального релиза
GitHub, сверяет SHA-256 с метаданными релиза и сохраняет бинарник в `.tools/xray`.
При отсутствии контрольной суммы или несовпадении существующее ядро не заменяется.

Чтобы запускать `vctl` из любой директории, создайте ссылку на launcher.
Следующие команды выполняются из корня проекта:

```sh
mkdir -p "$HOME/.local/bin"
ln -s "$PWD/scripts/vctl-launcher" "$HOME/.local/bin/vctl"
export PATH="$HOME/.local/bin:$PATH"
vctl --help
```

Для следующих сеансов добавьте строку `export PATH="$HOME/.local/bin:$PATH"`
в конфигурацию своей оболочки, например `~/.zshrc`. Если команда `vctl`
уже установлена, сначала проверьте её расположение через `command -v vctl`:
создание ссылки не перезаписывает существующий файл.

Launcher использует `.venv/bin/python`, если он существует, иначе `python3`
из PATH. Переменная `VCTL_PYTHON` позволяет указать другой интерпретатор.
После перемещения проекта пересоздайте ссылку и виртуальное окружение.

## Тестирование

```sh
.venv/bin/python -m unittest discover -s tests -v
VCTL_INTEGRATION=1 .venv/bin/python -m unittest discover -s tests -v
```

Основные тесты проверяют импорт подписок, генерацию конфигурации, хранение
настроек и восстановление DNS. При наличии `.tools/xray` также проверяется
валидность конфигураций реальным ядром. Интеграционные тесты запускают Xray
на loopback-интерфейсе, проверяют правила, обновление и остановку; TUN не включают.
Также проверяются распознавание процесса macOS, замена устаревшего IP по HTTP Host,
приоритеты DNS и пресетов, загрузка небольших тестовых protobuf-баз и отказ
от повреждённой базы. Проверка процесса использует помеченный `tun-in` SOCKS-вход:
это проверяет механизм libproc, но не заменяет испытание настоящего TUN с
UDP/QUIC, IPv6 и вспомогательными процессами конкретных приложений.

`scripts/tun-smoke.py` — отдельная ручная проверка реального TUN. Она требует
macOS, root, заполненного профиля и доступа в интернет; меняет маршруты,
а с `--full` также системный DNS. В ней предусмотрены очистка и независимый
таймер отката. Запускайте её только когда допустим временный перерыв связи.

Код разделён на CLI (`cli.py`), импорт (`profiles.py`), хранение и загрузку
подписок (`storage.py`), генерацию конфигурации (`config.py`), управление
процессами (`runtime.py`), привилегированный запуск (`tun.py`), DNS (`macos.py`)
и аварийную очистку (`watchdog.py`). Пресеты, загрузка и проверка GeoIP/GeoSite
находятся в `routing_data.py`.

Базы сохраняются в каталоге `geodata` общего профиля под именами SHA-256.
`XRAY_LOCATION_ASSET` передаётся и при проверке конфигурации, и при запуске ядра,
включая привилегированный TUN. Новая база не заменяет файл, на который ссылается
работающий конфиг. После проверки Xray новое состояние записывается атомарно;
неиспользуемые версии баз пока автоматически не удаляются.
Локальные пресеты кешируются в `state.json`; фоновый процесс обновляет только
HTTPS-источники. Периодическое обновление без изменения итогового конфига
не перезапускает ядро.

## Выпуск Homebrew-пакета

Формула использует GitHub-репозиторий как источник и закрепляет полный SHA
коммита через `revision`. Теги и загруженный бинарник клиента не нужны.
Архивы Xray закреплены по версии и SHA-256 для Apple Silicon и Intel.
Python-зависимостей за пределами стандартной библиотеки у приложения нет;
исходники устанавливаются в `libexec`, команда в `bin` запускает их через
объявленную зависимость Python.

Для выпуска обновления сначала опубликуйте коммит с изменениями приложения,
затем обновите SHA источника и версию формулы. Версия в `pyproject.toml` и
`version` в формуле должны совпадать; автоматической синхронизации нет.
В текущей схеме числовая ревизия пакета не используется. Зафиксируйте и отправьте изменение
формулы отдельным коммитом. Это позволяет формуле ссылаться на уже существующий
коммит без создания тега.

Проверка опубликованной формулы:

```sh
brew install --skip-link nagraver/vctl/vctl
brew test nagraver/vctl/vctl
```

`--skip-link` позволяет проверить пакет, не заменяя существующую команду
и дополнение zsh. Тест формулы проверяет пустой профиль, вывод дополнения и
версию ядра; TUN не запускается.
