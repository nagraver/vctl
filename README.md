# vctl

**VPN для macOS — из терминала.**

Подключайте подписки VLESS/Trojan, выбирайте сервер и задавайте исключения
для трафика. Системный TUN и локальный прокси на базе **Xray-core**.

**🍎 Apple Silicon и Intel · 📦 Homebrew · 🔀 Split tunneling · 🔄 Автообновление подписок**

## 📦 Установка

Нужны macOS и установленный Homebrew. Python, Xray и дополнение для zsh
устанавливаются вместе с клиентом.

```sh
brew trust --formula nagraver/vctl/vctl
brew tap nagraver/vctl https://github.com/nagraver/vctl.git
brew install nagraver/vctl/vctl
```

В Homebrew до версии 7, где нет команды `brew trust`, пропустите первую строку.

## 🚀 Первое подключение

```sh
vctl sub add       # вставьте ссылку на подписку в скрытый запрос
vctl tun start    # включите VPN для системы
vctl tun status   # проверьте состояние клиента
```

Имя подписки определяется автоматически. По умолчанию клиент выбирает сервер
автоматически и направляет захваченный трафик через VPN; частные сети идут напрямую.

Для отключения:

```sh
vctl tun stop
```

> [!NOTE]
> TUN запрашивает пароль macOS через `sudo`. Запускайте команды от обычного
> пользователя — добавлять `sudo` вручную не нужно.

> [!IMPORTANT]
> Автозапуск и kill switch пока не реализованы. После перезагрузки Mac VPN
> нужно включить снова. Остановка TUN возвращает обычную маршрутизацию.

## ⚡ На каждый день

| Задача | Команда |
| --- | --- |
| Включить VPN | `vctl tun start` |
| Выключить VPN | `vctl tun stop` |
| Перезапустить | `vctl tun restart` |
| Посмотреть состояние | `vctl tun status` |
| Проверить задержку серверов | `vctl ping` |
| Показать серверы и их ID | `vctl nodes` |
| Выбрать сервер | `vctl use NODE_ID` |
| Вернуть автоматический выбор | `vctl use auto` |
| Обновить подписки | `vctl sub update` |
| Показать правила | `vctl rule list` |
| Открыть справку | `vctl --help` |

Вместо `NODE_ID` подставьте ID из `vctl nodes`. Правила, подписки и выбранный
сервер сохраняются между запусками. Изменения настроек автоматически
применяются работающим клиентом; текущие соединения могут прерваться.

## 🔀 Что пускать через VPN

**Всё через VPN, выбранные сайты — напрямую:**

```sh
vctl default proxy
vctl rule add suffix example.org direct
```

**Только выбранные сайты через VPN:**

```sh
vctl default direct
vctl rule add suffix example.org proxy
```

Типы правил:

| Тип | Что совпадает | Пример |
| --- | --- | --- |
| `domain` | Только точный домен | `api.example.org` |
| `suffix` | Домен и все его поддомены | `example.org` |
| `cidr` | IP-подсеть | `203.0.113.0/24` |
| `geoip` | Страна или список IP из базы | `ru` |
| `geosite` | Набор доменов из базы | `youtube` |
| `process` | Имя процесса, только TUN | `curl` |
| `path` | Исполняемый файл или каталог приложения, только TUN | `/Applications/Firefox.app` |

Действия: `direct` — напрямую, `proxy` — через VPN, `block` — блокировать.

```sh
vctl rule add suffix ads.example.net block
vctl rule add cidr 203.0.113.0/24 direct
vctl rule list
vctl rule remove 2
```

Первое совпавшее пользовательское правило побеждает. Номер для удаления
возьмите из `rule list`. Для отдельного IP используйте `/32` (IPv4) или `/128`
(IPv6). Затем применяются включённые пресеты в порядке добавления,
исключения для частных сетей и маршрут по умолчанию. Служебные правила DNS
проверяются раньше всех правил пользователя.

### Приложения

```sh
vctl rule add path /Applications/Firefox.app direct
vctl rule add process curl proxy
vctl rule add path /usr/bin/curl direct
```

Путь с окончанием `.app` автоматически превращается в правило для всего
каталога приложения, включая исполняемые файлы внутри него. Для произвольного
каталога добавьте `/` в конце. Пути с пробелами заключайте в кавычки.
`process` сравнивает имя исполняемого файла, а не название окна приложения.

Эти правила применяются только к TUN. В локальном SOCKS/HTTP-прокси они
не действуют. Общесистемные помощники, расположенные за пределами `.app`,
могут потребовать отдельного правила. Если определить процесс не удалось,
проверяются следующие правила и маршрут по умолчанию. DNS-запросы через
системный резолвер не сохраняют принадлежность к исходному приложению:
для них действуют доменные правила DNS.

### GeoIP и GeoSite

Сначала загрузите базы:

```sh
vctl geodata update
vctl rule add geoip ru direct
vctl rule add geosite youtube proxy
vctl geodata status
```

По умолчанию используются [базы Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat).
Они обновляются раз в сутки, пока клиент работает. Доступные категории зависят
от выбранной базы. GeoIP определяет принадлежность IP-сети, а не язык или
владельца сайта; для конкретных сервисов обычно точнее GeoSite.

Собственные совместимые базы можно подключить через `geodata update
--geoip-url HTTPS_URL --geosite-url HTTPS_URL --interval 86400`.
Перед применением базы проверяются Xray; при ошибке сохраняется рабочая версия.

### Пресеты

Пресет — именованный набор правил, который можно обновлять и отключать целиком:

```sh
vctl preset add ads builtin:ads       # после geodata update
vctl preset add work ./work.json
vctl preset list
vctl preset show work
vctl preset disable work
vctl preset enable work
vctl preset update work
vctl preset remove work
```

Вместо файла можно передать HTTPS-ссылку на JSON. Удалённые включённые пресеты
автоматически обновляются каждые 12 часов; при добавлении можно задать
`--interval 3600`. Локальные файлы перечитываются только по `preset update`.
Изменения файла не затрагивают сохранённую копию до обновления. Команда
`preset update` без имени обновляет все пресеты, сохраняя их порядок и состояние.

Формат `work.json`:

```json
{
  "version": 1,
  "description": "Рабочие сервисы напрямую",
  "rules": [
    {"kind": "suffix", "value": "example.org", "action": "direct"},
    {"kind": "path", "value": "/Applications/Firefox.app", "action": "direct"}
  ]
}
```

Поддерживаются все типы из таблицы выше. Это формат vctl, а не произвольный
конфиг Xray или YAML Clash. Лимит — 2 МБ и 5000 правил на пресет.
Встроенные пресеты: `builtin:lan` — частные сети напрямую,
`builtin:ads` — блокировка `geosite:category-ads-all`.
Личные правила из `rule add` имеют приоритет над любым пресетом.

### DNS и доменные исключения

```sh
vctl dns show
vctl dns set --direct https://1.1.1.1/dns-query
vctl dns set --proxy https://1.1.1.1/dns-query
vctl dns set --strategy UseIPv4
```

Последняя команда полезна для проверки проблем с IPv6; стандартный режим —
`UseIP` (IPv4 и IPv6). Также доступен `UseIPv6`. URL резолвера должен использовать
HTTPS и IP-адрес вместо имени, чтобы не возникала зависимость от системного DNS.

Доменные правила `direct` и `proxy` выбирают соответствующий DNS-маршрут.
Результат распознавания HTTP/TLS/QUIC используется для повторного разрешения
имени: устаревший IP приложения не закрепляет неправильный адрес назначения.
DNS учитывает порядок доменных правил и не переключается на противоположный
маршрут при ошибке подходящего резолвера.

`domain` относится только к одному имени; для сайта с поддоменами используйте
`suffix`. Ресурсы на других доменах, включая внешние CDN, требуют собственных
правил. Собственный DoH браузера и ECH могут мешать определению настоящего имени.
Если домен невозможно распознать, используйте правило приложения или IP.
FakeDNS не включён.

## Подписки

```sh
vctl sub add                       # имя из ответа сервера
vctl sub add home                  # собственное имя
vctl sub add work --interval 3600  # обновление каждый час
vctl sub list
vctl sub update                    # обновить все
vctl sub update home               # обновить одну
vctl sub remove work
```

Подписки обновляются **каждые 12 часов**, пока клиент запущен. Интервал задаётся
в секундах, минимум — 60. При ошибке фонового обновления сохраняется последняя
рабочая конфигурация; повторная попытка выполняется через 60 секунд.

При добавлении ссылка вводится скрыто. Опция `--url` также поддерживается,
но переданная через неё ссылка может сохраниться в истории терминала.
Допускаются только HTTPS-ссылки и ответы размером до 2 МБ.

<details>
<summary>Как определяются имена и выбирается сервер</summary>

Имя подписки берётся из `Profile-Title`, включая формат `base64:` с UTF-8.
Если название отсутствует или его кодировка некорректна, используется домен
ссылки. Совпадающие имена получают числовой суффикс. Имена с пробелами
заключайте в кавычки. Обновления не меняют сохранённое имя; повторное
добавление той же ссылки отклоняется.

`ping` измеряет длительность HTTPS-запроса через каждый сервер, а не ICMP.
Пользовательские исключения при проверке не применяются. Если все серверы
не прошли проверку, команда завершается с ошибкой.

`auto` использует Xray Observatory и `leastPing` с проверкой каждые 5 минут.
До первых результатов используется первый сервер. ID зависит от параметров
подключения, а не только от названия. Если явно выбранный сервер исчез,
нужно выбрать другой ID или `auto`.

</details>

## Локальный прокси

Если VPN нужен отдельному приложению, можно запустить SOCKS5/HTTP-прокси
без изменения системных маршрутов:

```sh
vctl start
curl --proxy socks5h://127.0.0.1:2080 https://example.com
vctl stop
```

| | Локальный прокси | Системный TUN |
| --- | --- | --- |
| Запуск | `vctl start` | `vctl tun start` |
| Перезапуск | `vctl restart` | `vctl tun restart` |
| Статус | `vctl status` | `vctl tun status` |
| Остановка | `vctl stop` | `vctl tun stop` |
| SOCKS5 / HTTP | `2080` / `2081` | `2180` / `2181` |
| Права root | Не нужны | Нужны |

Все прокси-порты слушают `127.0.0.1`. Оба режима используют общие настройки,
но отдельные процессы. Для локального прокси приложение нужно настроить вручную.

`run` вместо `start` запускает клиент в текущем терминале; Ctrl+C останавливает
его. `--port N` задаёт SOCKS-порт, HTTP использует `N+1`. `restart` сохраняет
текущие порты, если не передать новые; остановленный клиент запускается с
портами по умолчанию. Конфигурация проверяется перед остановкой процесса.

## Обновление и удаление

Перед обновлением остановите используемые режимы:

```sh
vctl tun stop
vctl stop
brew update
brew upgrade nagraver/vctl/vctl
```

После обновления запустите нужный режим снова. Для удаления также сначала
остановите клиент, затем выполните:

```sh
brew uninstall nagraver/vctl/vctl
```

Настройки в `~/.config/vctl` сохраняются при обновлении и удалении пакета.

## Конфигурация

**Основной файл — `~/.config/vctl/state.json`.** Он содержит подписки,
сохранённые серверы, правила, пресеты, параметры DNS, версии баз, выбор сервера
и политику по умолчанию.
Обычный прокси и TUN используют один файл.

Меняйте настройки командами CLI. Для ручного редактирования сначала
остановите оба режима, а после изменений выполните `vctl check`.

<details>
<summary>Структура каталога и дополнительные параметры</summary>

```text
~/.config/vctl/
├── state.json          # общие настройки
├── geodata/            # версии баз GeoIP/GeoSite, имена по SHA-256
├── config.json         # сгенерированный конфиг локального прокси
├── supervisor.log      # журнал управляющего процесса прокси
└── tun/                # служебные файлы TUN; каталог принадлежит root
    ├── config.json
    ├── supervisor.log
    ├── runtime.json
    └── dns-restore.json
```

Служебные файлы создаются по мере необходимости. Сокеты и файлы блокировок
в схеме опущены. `config.json` генерируется автоматически: ручные изменения
будут перезаписаны. Порты и путь к ядру задаются при запуске и в настройках
не сохраняются.

Другой профиль выбирается через `VCTL_HOME` или `--home`. Глобальные опции
указываются перед подкомандой:

```sh
vctl --home "$HOME/my-vpn-profile" sub add
vctl --home "$HOME/my-vpn-profile" tun start
vctl --core /absolute/path/to/xray check
```

Для запуска, статуса и остановки указывайте один и тот же профиль.
Приоритет выбора ядра: `--core`, `VCTL_CORE`, встроенный `.tools/xray`,
затем `xray` из PATH. При запуске из рабочей копии проекта профиль по умолчанию
находится в её `.local/`.

Каталог профиля имеет права 0700, настройки — 0600. В них есть ссылки подписок
и учётные данные серверов: не публикуйте файлы профиля.

</details>

## Диагностика

```sh
vctl doctor           # версия ядра, профиль, состояние локального прокси
vctl check --mode tun # проверка конфигурации без включения VPN
vctl ping             # проверка соединений с серверами
vctl tun status       # состояние TUN и последняя ошибка обновления
```

| Проблема | Что проверить |
| --- | --- |
| Команда не найдена | Наличие Homebrew в PATH и результат `brew list vctl`. |
| Подписка отклонена | Формат ответа и поддерживаемые параметры подключения. |
| Выбранный сервер исчез | `vctl nodes`, затем `vctl use NODE_ID` или `vctl use auto`. |
| TUN не запускается | `vctl ping`, доступ к sudo, занятость портов и `~/.config/vctl/tun/supervisor.log`. |
| Ошибка обновления | Поле `error` в статусе и результат `vctl sub update`. |
| После сбоя не восстановлен DNS | После остановки управляющего процесса — `vctl tun recover`. |

`status` показывает состояние процесса, а не гарантирует доступ в интернет.
`check` проверяет конфигурацию, а не доступность серверов. Журнал управляющего
процесса не является полным журналом Xray.

## Совместимость и ограничения

| Поддерживается | Пока не поддерживается |
| --- | --- |
| VLESS, Trojan | VMess, Shadowsocks |
| TLS, Reality, VLESS Vision | VLESS Encryption |
| TCP, WebSocket, gRPC, HTTPUpgrade | XHTTP, старые HTTP/H2-транспорты |
| Подписки со списком URI, plain/Base64 | JSON-конфигурации Xray, YAML-подписки |
| Домены, IP, GeoIP/GeoSite, процессы и пути приложений | Импорт произвольных форматов пресетов |

Подписка с неподдерживаемой записью отклоняется целиком; рабочий кеш сохраняется.
Ядро закреплено на Xray **26.9.9**. Версии клиента и сервера могут различаться,
если они поддерживают параметры соединения из подписки.

IPv6-маршруты создаются, но работа IPv6 от начала до конца пока не подтверждена.
Нет kill switch, автозапуска при входе в macOS и интерфейса в строке меню.
Другие VPN могут конфликтовать с маршрутами и DNS.

## Как устроены TUN и DNS

<details>
<summary>Маршруты, разрешение имён и аварийное восстановление</summary>

Используется нативный TUN Xray, без отдельного tun2socks. Ядро создаёт
виртуальный интерфейс и маршруты, привязывает исходящие соединения к физическому
интерфейсу. Имена VPN-серверов разрешаются до запуска TUN; TLS SNI сохраняется.

Клиент временно назначает активным сетевым службам DNS `198.19.255.53`.
Запросы на порт 53 перехватывает DNS Xray. Основной резолвер —
`https://1.1.1.1/dns-query`: через VPN при `default proxy`, напрямую при
`default direct`. Доменные исключения выбирают свой DNS-маршрут; адреса
резолверов меняются через `dns set`. Прямой DoH проходит через outbound `direct`,
а не через отдельный локальный транспорт в обход маршрутизатора Xray.
Собственный DoH приложений подчиняется обычным правилам HTTPS-маршрутизации.

Служебные правила DNS имеют приоритет над пользовательскими. Пользовательские
правила проверяются перед исключениями для частных сетей и политикой по
умолчанию. Для доменного правила ядро должно определить имя назначения;
если это невозможно, используйте IP-правило.

При остановке ядра удаляются его маршруты; клиент восстанавливает прежние DNS.
Значения DNS, изменённые другой программой, не перезаписываются. Защитный процесс
выполняет очистку при аварии управляющего процесса.

`vctl tun recover` нужен, если автоматическая очистка не завершилась. Он
завершает оставшееся ядро данного профиля, восстанавливает DNS по журналу и
удаляет служебное состояние. При работающем управляющем процессе команда
отказывается выполнять восстановление. Это не общая команда ремонта сети.

Только управление TUN требует root. Подписки и правила редактируются от
обычного пользователя. Клиент не меняет `sudoers`.

</details>
