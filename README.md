# vctl

CLI-клиент для macOS на базе Xray-core. Загружает подписки VLESS/Trojan,
проверяет доступность серверов и направляет трафик через локальный прокси
или системный TUN. Настройки хранятся в одном файле внутри проекта.

## Возможности и ограничения

- Подписки по HTTPS в формате списка URI или Base64, автоматическое обновление.
- Ручной выбор сервера или автоматический выбор по задержке.
- SOCKS5/HTTP-прокси и системный TUN с настройкой маршрутов и DNS.
- Правила по доменам и IP-подсетям: напрямую, через VPN или блокировка.
- Восстановление DNS при остановке и защитный процесс для аварийной очистки.

Поддерживаются VLESS и Trojan, TLS/Reality, VLESS Vision, TCP, WebSocket,
gRPC и HTTPUpgrade. VMess, Shadowsocks, XHTTP, VLESS Encryption, старые HTTP/H2
транспорты, JSON-конфигурации Xray и YAML-подписки не поддерживаются импортером.
Подписка с неподдерживаемой записью отклоняется целиком; рабочий кеш сохраняется.

Разделение по приложениям, kill switch, интерфейс в строке меню и автозапуск
при входе в macOS не реализованы. TUN создаёт IPv4/IPv6-маршруты, но работа
IPv6 от начала до конца пока не подтверждена. Остановка TUN возвращает обычную
маршрутизацию; клиент не гарантирует блокировку прямого трафика при сбое.

## Требования

- macOS на Apple Silicon или Intel.
- Python 3.11 или новее.
- Системный `curl`.
- Xray-core. Установщик проекта закреплён на версии **26.9.9**.
- Доступ к `sudo` для управления TUN. Локальный прокси работает без root.

Сторонних Python-зависимостей для запуска нет. Версия ядра на сервере не
обязана совпадать с клиентской; сервер должен поддерживать параметры
соединения, указанные в подписке.

## Установка из исходников

Скачайте репозиторий и откройте терминал в его каталоге. Проверьте, что
`python3 --version` показывает Python 3.11 или новее, затем выполните:

```sh
python3 -m venv .venv
.venv/bin/python scripts/install-core.py
./scripts/vctl-launcher --help
```

Установщик скачивает архив Xray для архитектуры Mac из официального релиза
GitHub, сверяет SHA-256 с метаданными релиза и сохраняет бинарник в `.tools/xray`.
При отсутствии контрольной суммы или несовпадении существующее ядро не заменяется.

Чтобы запускать `vctl` из любой директории, создайте ссылку на launcher.
Следующие команды выполняются из корня проекта:

```sh
mkdir -p "$HOME/.local/bin"
ln -s "$PWD/scripts/vctl-launcher" "$HOME/.local/bin/vctl"
export PATH="$HOME/.local/bin:$PATH"
vctl --help
```

Для следующих сеансов добавьте строку `export PATH="$HOME/.local/bin:$PATH"`
в конфигурацию своей оболочки, например `~/.zshrc`. Если команда `vctl`
уже установлена, сначала проверьте её расположение через `command -v vctl`:
создание ссылки не перезаписывает существующий файл.

Launcher использует `.venv/bin/python`, если он существует, иначе `python3`
из PATH. Переменная `VCTL_PYTHON` позволяет указать другой интерпретатор.
После перемещения проекта пересоздайте ссылку и виртуальное окружение.

## Быстрый старт

Добавьте подписку, вставив ссылку в скрытый запрос:

```sh
vctl sub add
vctl nodes
vctl ping
vctl use auto
vctl check --mode tun
vctl tun start
vctl tun status
```

`tun start` автоматически вызывает `sudo` и при необходимости запрашивает
пароль macOS. Перед настройкой сети клиент проверяет доступность серверов.
Запускайте команду от обычного пользователя, без внешнего `sudo`.

По умолчанию захваченный трафик направляется через VPN, частные сети — напрямую.
Для остановки:

```sh
vctl tun stop
```

Настройки сохраняются между запусками, но после перезагрузки Mac подключение
нужно запустить снова. Другие VPN могут конфликтовать с маршрутами и DNS TUN.

## Режимы работы

| Режим            | Запуск в фоне    | Статус            | Остановка       | SOCKS5 / HTTP   |
| ---------------- | ---------------- | ----------------- | --------------- | --------------- |
| Локальный прокси | `vctl start`     | `vctl status`     | `vctl stop`     | `2080` / `2081` |
| Системный TUN    | `vctl tun start` | `vctl tun status` | `vctl tun stop` | `2180` / `2181` |

Все прокси-порты слушают только `127.0.0.1`. Локальный прокси не меняет
системные маршруты: приложение нужно настроить на использование прокси.

```sh
vctl start
curl --proxy socks5h://127.0.0.1:2080 https://example.com
curl --proxy http://127.0.0.1:2081 https://example.com
vctl stop
```

Перезапуск с сохранением текущих портов:

```sh
vctl restart
vctl tun restart
```

Если процесс остановлен, `restart` запускает его с портами по умолчанию.
`--port N` позволяет изменить порт при перезапуске. Конфигурация проверяется
до остановки работающего процесса; перезапуск прерывает текущие соединения.

`run` вместо `start` оставляет управляющий процесс в текущем терминале;
Ctrl+C останавливает клиент. Для TUN используется `vctl tun run`.

Опция `--port N` задаёт SOCKS-порт; HTTP использует `N+1`:

```sh
vctl start --port 3080
vctl tun start --port 3180
```

Оба режима используют общие настройки, но отдельные процессы и служебные файлы.
Команды `status` показывают состояние процесса, порты и последнюю ошибку
обновления; это не проверка доступа в интернет.

## Автодополнение zsh

Дополнение поставляется как стандартный файл zsh `_vctl`. Для Homebrew
создайте ссылку в каталоге дополнений (из корня проекта):

```sh
ln -s "$PWD/vless_client/completions/_vctl" "$(brew --prefix)/share/zsh/site-functions/_vctl"
```

Каталог Homebrew `share/zsh/site-functions` должен входить в `$fpath` до
инициализации `compinit`. Если используется системный zsh и Oh My Zsh,
добавьте каталог **перед** строкой `source .../oh-my-zsh.sh` в `~/.zshrc`:

```sh
# Apple Silicon; для Intel Homebrew замените /opt/homebrew на /usr/local.
fpath=(/opt/homebrew/share/zsh/site-functions $fpath)
```

После установки откройте новый терминал. Oh My Zsh
инициализирует систему дополнений самостоятельно; для обычного zsh добавьте
`autoload -Uz compinit` и `compinit` в `~/.zshrc`, если их ещё нет.

Без Homebrew добавьте каталог проекта в `$fpath` перед `compinit` или загрузкой
Oh My Zsh (замените путь на свой):

```sh
fpath=(/absolute/path/to/project/vless_client/completions $fpath)
```

Установка файла не обновляет уже открытые оболочки. Если каталог дополнений
уже есть в `$fpath`, активируйте его в текущем терминале:

```sh
autoload -Uz _vctl
compdef _vctl vctl
```

Для проверки наберите `vctl tun res` и нажмите Tab: слово должно дополниться
до `restart`. Это дополнение по Tab, а не подсказки при каждом нажатии клавиши.

Дополнение загружается zsh по требованию: запуск `vctl` при каждом открытии
терминала не нужен. Команда `vctl completion zsh` выводит содержимое файла для
установщиков; её вывод нужно сохранить как `_vctl` в каталоге из `$fpath`.
После перемещения проекта пересоздайте ссылку либо обновите `$fpath`.

Tab подсказывает команды и подкоманды, параметры, типы правил, действия
`direct/proxy/block`, режимы `proxy/tun` и пути для `--home`/`--core`.
Дополнение работает локально без sudo и сетевых запросов. Имена подписок
и ID серверов пока вводятся вручную. Другие оболочки пока не поддерживаются.

## Подписки и серверы

```sh
vctl sub add                       # имя из ответа сервера
vctl sub add home                  # собственное имя
vctl sub add work --interval 3600  # обновление каждый час
vctl sub list
vctl sub update                    # обновить все подписки сейчас
vctl sub update home
vctl sub remove work
```

Ссылку можно передать через `--url`, но тогда она может попасть в историю
оболочки. Без этой опции ввод скрыт. Допускаются только HTTPS-ссылки;
максимальный размер ответа — 2 МБ.

Автоматическое имя берётся из заголовка `Profile-Title`, в том числе
`base64:` с UTF-8. Если заголовка нет или его кодировка некорректна,
используется домен ссылки. При совпадении имён добавляется числовой суффикс.
Имена с пробелами заключайте в кавычки. Обновление не меняет сохранённое имя;
повторное добавление той же ссылки отклоняется.

Интервал обновления задаётся в секундах: по умолчанию 43200 (12 часов),
минимум 60. Заголовки сервера не переопределяют интервал. Автообновление
выполняется только пока работает управляющий процесс. При ошибке фонового
обновления сохраняется последняя рабочая конфигурация; повторная попытка —
через 60 секунд.

```sh
vctl nodes
vctl use NODE_ID
vctl use auto
vctl ping
```

Вместо `NODE_ID` подставьте идентификатор из `nodes`. Идентификатор зависит
от параметров подключения и не меняется только из-за переименования сервера.
Если выбранный сервер исчез, выберите другой ID или `auto`.

`ping` измеряет длительность HTTPS-запроса через каждый сервер, а не ICMP.
Пользовательские правила при проверке не применяются. Если все проверки
неуспешны, команда завершится с ошибкой. `auto` использует Xray Observatory
и `leastPing`: проверки выполняются каждые 5 минут, до первых результатов
используется первый сервер.

## Маршрутизация и split tunneling

Формат команды:

```text
vctl rule add KIND VALUE ACTION
```

| KIND     | Значение              | Пример            |
| -------- | --------------------- | ----------------- |
| `domain` | Точный домен          | `api.example.org` |
| `suffix` | Домен и его поддомены | `example.org`     |
| `cidr`   | IPv4/IPv6-подсеть     | `203.0.113.0/24`  |

Действия: `direct` — напрямую, `proxy` — через выбранный VPN-сервер,
`block` — блокировать. Для отдельного IP используйте `/32` (IPv4) или `/128` (IPv6).

```sh
vctl rule add suffix example.org direct
vctl rule add domain api.example.net proxy
vctl rule add suffix ads.example.net block
vctl rule add cidr 203.0.113.0/24 direct
vctl rule list
vctl rule remove 2
```

Первое совпавшее пользовательское правило побеждает. Номера для удаления
показывает `rule list`. Пользовательские правила проверяются перед встроенными
исключениями для частных сетей и политикой по умолчанию. Обработка DNS выделена
в служебные правила, которые имеют более высокий приоритет.

```sh
vctl default proxy  # весь остальной трафик через VPN
vctl default direct # весь остальной трафик напрямую
```

Для схемы «только выбранные сайты через VPN» установите `default direct`
и добавьте правила с действием `proxy`. Доменные правила требуют, чтобы ядро
могло определить имя назначения; для соединений без доступного домена
используйте IP-правила.

Изменения применяются работающим клиентом автоматически, через перезапуск
ядра. Уже открытые соединения могут оборваться.

## TUN, DNS и права доступа

TUN реализован нативным входящим подключением Xray, без отдельного tun2socks.
Ядро создаёт виртуальный интерфейс и маршруты, привязывает исходящие соединения
к физическому интерфейсу. Имена VPN-серверов разрешаются до запуска TUN,
TLS SNI сохраняется.

Клиент временно назначает активным сетевым службам DNS `198.19.255.53`.
Запросы на порт 53 перехватываются встроенным DNS Xray. Основной резолвер —
DoH `https://1.1.1.1/dns-query`: через VPN при `default proxy`, напрямую при
`default direct`. Для доменных исключений `direct` используется прямой DoH.
Приложения с собственным DoH подчиняются обычным правилам HTTPS-маршрутизации.

При остановке ядра удаляются его маршруты; клиент восстанавливает прежние DNS.
Если другая программа успела изменить DNS, её значение не перезаписывается.
Отдельный защитный процесс выполняет очистку при аварии управляющего процесса.

```sh
vctl tun recover
```

`recover` нужен, если автоматическая очистка не завершилась: он завершает
оставшееся ядро данного профиля, восстанавливает DNS по сохранённому журналу
и удаляет служебное состояние. При работающем управляющем процессе команда
отказывается выполнять восстановление. Это не общая команда ремонта сети.

TUN работает с root через `sudo`; изменение правил, подписок и выбор сервера
выполняются от обычного пользователя. Клиент не меняет `sudoers`.

## Файлы и конфигурация

По умолчанию профиль расположен в `.local/` относительно корня проекта,
независимо от текущей директории терминала:

```text
.local/
├── state.json          # общие настройки, подписки и сохранённые серверы
├── config.json         # сгенерированный конфиг локального прокси
├── supervisor.log      # журнал управляющего процесса прокси
└── tun/                # служебный каталог TUN, принадлежит root
    ├── config.json
    ├── supervisor.log
    ├── runtime.json     # состояние для аварийной очистки
    └── dns-restore.json # настройки DNS для восстановления
```

Служебные файлы создаются по мере необходимости; сокеты и файлы блокировок
в схеме опущены. Отдельного файла настроек для TUN нет.

`state.json` хранит подписки, кеш серверов, интервалы и время обновления,
выбранный сервер, правила, `default` и `test_url`. Настройки можно менять через
CLI или вручную после остановки обоих режимов. Пример элемента массива `rules`:

```json
{ "kind": "suffix", "value": "example.org", "action": "direct" }
```

После ручного редактирования выполните `vctl check`. Сгенерированные
`config.json` редактировать не следует: клиент перезаписывает их при запуске
и применении настроек. Порты и путь к ядру задаются при запуске, в `state.json`
они не сохраняются.

Другой каталог можно выбрать переменной `VCTL_HOME` или глобальной опцией
`--home`. Опции `--home` и `--core` указываются перед подкомандой:

```sh
vctl --home "$HOME/my-vpn-profile" sub add
vctl --home "$HOME/my-vpn-profile" tun start
vctl --core /absolute/path/to/xray check
```

Используйте один и тот же профиль для запуска, статуса и остановки. Приоритет
выбора ядра: `--core`, `VCTL_CORE`, `.tools/xray`, затем `xray` из PATH.

Каталог профиля имеет права 0700, файлы настроек — 0600. Они содержат ссылки
подписок и учётные данные серверов. `.local/` и `.tools/` исключены из Git;
при публикации архива также исключите их. Перед перемещением или удалением
проекта остановите прокси и TUN, чтобы сохранить возможность восстановления DNS.

## Диагностика

```sh
vctl --help
vctl sub --help
vctl tun --help
vctl doctor
vctl check
vctl check --mode tun
vctl ping
vctl tun status
```

`doctor` показывает версию ядра, путь профиля и состояние обычного прокси;
для TUN используйте `tun status`. `check` проверяет конфигурацию ядром, не
включая VPN и не проверяя доступность серверов. `ping` проверяет соединения.

| Проблема                       | Что проверить                                                                          |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| Команда не найдена             | Ссылку на launcher и наличие её каталога в PATH.                                       |
| Ядро не найдено                | Запустите `scripts/install-core.py` через Python проекта либо задайте `--core`.        |
| Подписка отклонена             | Формат ответа и поддерживаемые протоколы/параметры.                                    |
| Выбранный сервер исчез         | Выполните `nodes`, затем `use NODE_ID` или `use auto`.                                 |
| TUN не запускается             | Результат `ping`, доступ к sudo, занятость портов, журнал `.local/tun/supervisor.log`. |
| Ошибка обновления              | Поле `error` в статусе, доступность ссылки и результат `sub update`.                   |
| После сбоя не восстановлен DNS | После остановки управляющего процесса выполните `tun recover`.                         |

Диагностика ядра, которая может содержать секреты, не выводится напрямую в
терминал. Журнал управляющего процесса не является полным журналом Xray.

## Разработка и тестирование

```sh
.venv/bin/python -m unittest discover -s tests -v
VCTL_INTEGRATION=1 .venv/bin/python -m unittest discover -s tests -v
```

Основные тесты проверяют импорт подписок, генерацию конфигурации, хранение
настроек и восстановление DNS. При наличии `.tools/xray` также проверяется
валидность конфигураций реальным ядром. Интеграционные тесты запускают Xray
на loopback-интерфейсе, проверяют правила, обновление и остановку; TUN не включают.

`scripts/tun-smoke.py` — отдельная ручная проверка реального TUN. Она требует
macOS, root, заполненного профиля и доступа в интернет; меняет маршруты,
а с `--full` также системный DNS. В ней предусмотрены очистка и независимый
таймер отката. Запускайте её только когда допустим временный перерыв связи.

Код разделён на CLI (`cli.py`), импорт (`profiles.py`), хранение и загрузку
подписок (`storage.py`), генерацию конфигурации (`config.py`), управление
процессами (`runtime.py`), привилегированный запуск (`tun.py`), DNS (`macos.py`)
и аварийную очистку (`watchdog.py`).
